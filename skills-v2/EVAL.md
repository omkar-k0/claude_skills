# EVAL: skills v2

## Method

- Each skill was tested with two prompts, one routine and one ambiguous or adversarial, written as messages Omkar would actually send.
- Each prompt was run by a fresh-context subagent (Claude Sonnet, chosen because the goal is to make any Claude model behave well, and because it is cheaper) with exactly one skill folder loaded: its SKILL.md and references/ only. The subagent could not read the other skills, rigor-core, skills-current/, CONTEXT.md, or the changelog. So every skill was tested without rigor-core loaded, which is the stricter case.
- Subagents had web search, fetch, file read and python where the skill calls for them. No vault tool existed in any run.
- Judging was done by the orchestrating session against the skill's own rules (its Gate, its Hard rules, and the rigor-core pointer). PASS means every rule that the prompt exercised was followed. A rule the prompt did not touch is not counted.
- Verbatim outputs are in the session scratchpad (`eval/out/*.md`), not committed; the judgment and the reason are recorded here.
- Fixtures: a synthetic 30-firm monthly panel CSV (2,096 rows) for panel-regression-rigor, and a 4-section seminar-paper excerpt with page numbers for oral-defense-simulator.
